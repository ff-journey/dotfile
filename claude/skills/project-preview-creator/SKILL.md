# Project Review Creator — 题库式项目复习 Skill 生成器

分析目标项目，生成独立的 `project-review` skill（固定题库 + 苏格拉底式顺序复习 + 章节评分 + 进度持久化），可被 Claude Code 直接加载使用。

---

## 启动时确认

1. **目标项目路径**（默认当前工作目录）
2. **skill 输出路径**（默认 `{项目根目录}/.claude/skills/project-review/`）
3. **学习侧重**：特别想深入的模块？（可选，默认全覆盖）
4. **语言**（默认中文）

用户不指定则用默认值直接启动。

---

## 生成流程

### Phase 1：项目深度分析

用 Agent（subagent_type=Explore, thoroughness=very thorough）探索项目，收集：

| 维度 | 要收集的信息 |
|------|-------------|
| 项目定位 | 名称、解决什么问题、目标用户 |
| 技术栈 | 语言、框架、构建工具、关键依赖版本 |
| 架构分层 | 服务/模块划分、各自职责、协作关系 |
| 核心流程 | 请求链路、数据流、关键业务流程 |
| 设计决策 | 为什么选某技术、有哪些 trade-off |
| 存储 | 数据库/缓存/消息队列/文件存储 |
| 工程实践 | 测试、CI/CD、部署、配置管理 |
| 扩展点 | 如何添加新功能、插件/模块化机制 |

信息来源优先级：**代码 > 配置文件 > README > git 历史**

### Phase 2：设计章节结构

将知识点组织为 **5-12 章**，每章可含子章节（如 2A、2B、2C）。

**排列原则**：
- 第 1 章固定为"项目全景与设计理念"
- 中间章节按模块依赖顺序，每个核心模块/服务独立成章
- 大模块拆为子章节（如 Loader/Splitter/Transform/Embedding 各自成子章节）
- 横切关注点（测试/部署/可观测性）放末尾

完成后向用户展示章节大纲（含每章预估题数和难度分布），等待确认或调整。

### Phase 3：生成题库

写入 `references/question_bank.md`。总题量控制在 **40-100 题**，每章 **5-18 题**。

**每道题格式**：

```markdown
| # | 题目 | 难度 | 考察要点 | 参考答案要点 |
|---|------|------|---------|------------|
| {章号}-{序号} | {问题} | ⭐/⭐⭐/⭐⭐⭐ | {考察点} | {答案要点，含文件路径/类名} |
```

子章节用字母编号：`2A-01`, `2B-03`, `3A-02`。

**难度分配**：⭐基础 30% / ⭐⭐进阶 45% / ⭐⭐⭐深挖 25%

**出题原则**：
- ⭐：定义、职责、输入输出（"是什么"）
- ⭐⭐：原理、流程、参数影响、技术选型理由（"怎么做"）
- ⭐⭐⭐：设计决策、trade-off、跨模块协调、边界条件（"为什么"）
- 参考答案**必须包含具体文件路径/类名/方法名**
- 避免纯记忆题，侧重理解和推理
- 生成前验证所有引用的文件路径确实存在

### Phase 4：生成 Skill 文件

生成以下目录结构：

```
.claude/skills/project-review/
├── SKILL.md              # 复习老师 Agent 指令
├── review_progress.md    # 初始进度文件
└── references/
    └── question_bank.md  # 完整题库
```

#### SKILL.md 生成规则

参照 `references/skill_template.md` 模板，替换以下变量：

| 变量 | 替换为 |
|------|--------|
| `{{PROJECT_NAME}}` | 项目名称 |
| `{{TOTAL_QUESTIONS}}` | 总题数 |
| `{{CHAPTER_COUNT}}` | 章节数 |
| `{{CHAPTER_TABLE}}` | 章节概览表（章节名、题数、难度分布） |
| `{{CHAPTER_PROGRESS_TABLE}}` | 进度追踪表模板（章节名、掌握评分、已完成、待复习） |

#### review_progress.md 初始化

参照 `references/progress_template.md` 模板生成：所有章节 0 题完成、评分为 `—`。

### Phase 5：交付

向用户展示：
1. 章节结构 + 题数 + 难度分布概览表
2. 生成文件路径
3. 触发使用方式（如"说'开始复习'即可启动"）

---

## 关键约束

- 题目是**固定题库**，在生成时确定，运行时按顺序出题
- 每章控制在 5-18 题，保持复习节奏
- 项目超过 10 个模块时，建议用户选择重点模块
- 所有文件路径、类名必须基于实际代码，不编造
- 生成前验证所有引用的文件路径确实存在
