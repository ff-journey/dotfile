# Interview Prep Creator — 模拟面试 Skill 生成器

分析目标项目，生成独立的 `interview-prep` skill（5 种面试官风格 + 掷骰随机选题 + 简历包装识别 + 多维评分报告），可被 Claude Code 直接加载使用。

---

## 启动时确认

1. **目标项目路径**（默认当前工作目录）
2. **skill 输出路径**（默认 `{项目根目录}/.claude/skills/interview-prep/`）
3. **技术侧重**：特别想覆盖的模块？（可选，默认全覆盖）
4. **语言**（默认中文）

用户不指定则用默认值直接启动。

---

## 生成流程

### Phase 1：项目深度分析

用 Agent（subagent_type=Explore, thoroughness=very thorough）探索项目，收集：

| 维度 | 要收集的信息 |
|------|-------------|
| 项目定位 | 名称、解决什么问题、目标用户 |
| 技术栈 | 语言、框架、构建工具、关键依赖版本 |
| 架构分层 | 服务/模块划分、各自职责、协作关系 |
| 核心流程 | 请求链路、数据流、关键业务流程 |
| 设计决策 | 为什么选某技术、有哪些 trade-off |
| 存储 | 数据库/缓存/消息队列/文件存储 |
| 工程实践 | 测试、CI/CD、部署、配置管理 |
| 扩展点 | 如何添加新功能、插件/模块化机制 |
| 核心算法 | 关键算法/公式、参数含义、调优经验 |
| 幂等/一致性 | ID 生成策略、去重机制、多存储协调 |

信息来源优先级：**代码 > 配置文件 > README > git 历史**

### Phase 2：生成项目知识库

写入 `references/project_knowledge.md`。按模块组织，每个模块包含：

- **核心实现**：关键设计、算法、数据结构、文件路径
- **高频面试题**（2-4 道/模块）：Q&A 格式，答案必须引用真实代码路径/类名/函数名

**模块划分原则**：
- 每个核心功能模块独立成章（如检索、排序、数据处理、存储、API 层等）
- 横切关注点（测试、可观测性、部署）独立成章
- 总计 6-12 个模块

完成后向用户展示模块列表和每模块知识点概要，等待确认或调整。

### Phase 3：生成三方向题库

写入 `references/question_bank.md`。三方向结构：

#### 方向 1：项目综述
- **开场题池**（12 道）：覆盖架构全貌、核心流程、设计理念、工程化亮点
- **追问候选池**（8-10 道）：供即兴追问获取灵感用，不直接选取

#### 方向 2：简历深挖（包装识别）
- **P1 — 量化指标追问池**（6 道）：针对简历中的数字
- **P2 — 强动词追问池**（6-8 道）：针对"主导/设计/独立完成"
- **P3 — 技术词汇追问池**（8-10 道）：针对简历中的技术关键词
- **无简历题库**（6-8 道）：无简历时使用

#### 方向 3：技术深挖
- 按主题分组（A-G 共 5-7 组），每组 6-10 道，总计 **40-70 道**
- 主题组覆盖项目所有核心模块 + 通用系统设计

**出题原则**：
- 题目必须引用项目真实代码/架构，不编造
- 难度递进：是什么 → 怎么做 → 为什么 → trade-off
- 方向 2 的题目模板需留 `X%`/`{简历描述}` 占位符，运行时结合简历填充
- 生成前验证所有引用的文件路径确实存在

### Phase 4：生成报告模板

写入 `references/report_template.md`。包含：

1. **报告 Markdown 模板**：面试记录表格（含锚链接）、包装点评、综合评价、评分表
2. **预置参考答案库**：为 Phase 2 知识库中的高频面试题生成带 `<a id>` 锚点的参考答案（10-15 道核心题），运行时按需复制到报告
3. **评分细则**：5 个维度 + 5 档标准（9-10/7-8/5-6/3-4/1-2）

**评分维度需根据项目特点调整**，通用维度：
- 项目架构掌握
- 简历真实性
- 核心技术深度（根据项目特点命名，如"算法理论深度"/"系统设计深度"）
- 实现细节掌握
- 表达清晰度

### Phase 5：生成 Skill 文件

参照 `references/skill_template.md` 模板，替换以下变量生成 SKILL.md：

| 变量 | 替换为 |
|------|--------|
| `{{PROJECT_NAME}}` | 项目名称 |
| `{{PROJECT_DOMAIN}}` | 项目技术领域（如 "RAG / LLM Application" ） |
| `{{DIRECTION3_TOTAL}}` | 方向 3 题目总数 |
| `{{DIRECTION3_GROUPS}}` | 方向 3 主题组列表及关键词 |
| `{{SCORING_DIMENSIONS}}` | 5 个评分维度表 |
| `{{TRIGGERS}}` | 触发词 |

生成目录结构：

```
.claude/skills/interview-prep/
├── SKILL.md                    # 面试官 Agent 指令
└── references/
    ├── project_knowledge.md    # 项目知识库
    ├── question_bank.md        # 三方向题库
    └── report_template.md      # 报告模板 + 参考答案 + 评分细则
```

### Phase 6：交付

向用户展示：
1. 模块 × 知识点概览
2. 三方向题目数量统计
3. 生成文件路径
4. 触发使用方式（如"说'模拟面试'即可启动"）

---

## 关键约束

- 方向 3 题目总量控制在 40-70 道，太多会导致题库臃肿
- 项目超过 10 个模块时，建议用户选择重点模块
- 所有文件路径、类名、函数名必须基于实际代码，不编造
- 生成前验证所有引用的文件路径确实存在
- 题库中的参考答案必须精确到代码级别（文件路径 + 类名/函数名）
- 报告模板中的评分维度需根据项目技术特点定制
